\section{Code overview}
\label{sec:code}

\begin{description}[leftmargin=2.1em, style=nextline]
	\item[\texttt{models.py}]  
	Implements the five architectures required in Q\,3:  
	\textbf{Canonisation\_Net}, \textbf{Symmetrization\_Net},
	\textbf{Sampled\_Symmetrization\_Net},
	\textbf{Linear\_eq\_Net} (built from two equivariant layers),
	and \textbf{AugmentedInvariantNet}.  
	Each class exposes \texttt{forward(X)} with $X\in\mathbb R^{N\times d}$ drawn from a synthetic white-Gaussian \emph{matrix} generated by \verb|torch.randn|.
	
	\item[\texttt{utils.py}]  
	\begin{itemize}[nosep,leftmargin=1.2em]
		\item Permutation helpers: \texttt{create\_permutations\_sampled}.
		\item \emph{Unit tests} for invariance/equivariance
		(\texttt{test\_canonization\_net}, \dots).
		\item Training routine
		\texttt{train\_variance\_net} that learns variance purely from
		permutation augmentations.
	\end{itemize}
	
	\item[\texttt{main.py}]  
	Orchestrates the workflow:
	\begin{enumerate}[leftmargin=2em]
		\item runs each invariance test $50$ times and prints the failure rate;
		\item trains the variance model for $200$ epochs on a fixed set
		of size $N=50,\;d=5$;
		\item re‑tests the trained model for invariance.
	\end{enumerate}
\end{description}

\section{Permutation–invariance sanity check}
\label{sec:inv}

\subsection*{test Permutation invariance}
For every network we apply $50$ random permutations $P\!\in\!S_N$ to a fixed
set $X$ and record a \emph{failure} when the $\ell_\infty$–distance between the
original and permuted outputs exceeds a model‑specific tolerance:

\begin{itemize}
	\item[(a,b,d)] \hspace*{0.5em}fail if \( \lVert f(X)-f(PX)\rVert_\infty > 10^{-5} \);
	\item[(c)]      \hspace*{1.4em}fail if \( \lVert f(X)-f(PX)\rVert_\infty > 2\times10^{-1} \)\\
	(higher threshold to reflect the Monte‑Carlo approximation of \(S_N\));
	\item[(e)]      \hspace*{1.4em}fail if \( \lVert f(X)-f(PX)\rVert_\infty > 5\times10^{-2} \)\\
	(relaxed tolerance to probe the invariance learned via augmentation).
\end{itemize}
Finally, for each model we report the \emph{failure rate}
\[
\text{Failure rate}
\;=\;
\frac{\#\;\text{failed permutations}}
{\#\;\text{permutations tested}}\;,
\]
i.e.\ the fraction of the $50$ sampled permutations that violate
their respective tolerance.

\subsection*{Discussion}
\begin{itemize}[leftmargin=1.5em,itemsep=0.3em]
	\item \textbf{Exact symmetry methods.}
	Canonisation, full symmetrisation, and linear $S_N$‑equivariant layers are
	provably invariant; failures are zero within numerical precision.
	
	\item \textbf{Monte‑Carlo method (c).}
	Sampled symmetrisation averages over $K=0.05 \cdot 8! $ permutations—
	$\approx0.05\,|S_N|$ for $N=8$ - so estimator variance might explain the
	$\approx1\%$ failure rate.  Increasing $K$ should decrease the error.
	
	\item \textbf{Learned invariance (e).}
	The unconstrained MLP acquires symmetry through augmentation; after
	$\sim250$ epochs with $\sim500$ augmentations per epoch the failure rate falls below $0.3\%$.
\end{itemize}

\vspace{0.3em}
\noindent$^{\ast}$ Both stochastic models (c and e) pass with a looser
tolerance, We intentionally kept a looser threshold here to reveal the \emph{trend}
toward invariance and to assess given our time and computation resources how far each model has progressed toward full
invariance.
\subsection{Networks: theory \& implementation details}
\begin{enumerate}[label=(\alph*),wide,labelindent=0pt]	
	%------------------------------------------------------------------------
	\item \textbf{Canonisation Net}
	%
	\textit{Theory.}  
	A canoniser \(g\) assigns every permutation orbit to a single representative.
	We have
	$f(g(x)x) = f(g(y)y)$ whenever $x$ and $y$ are in the same orbit thereby proving exact permutation invariance.
%
	\textit{Implementation.}  
	We define the Canonization function \(g\) by sorting the rows according to \emph{descending} Euclidean‑norm order (computed over the feature
	dimension) with PyTorch sort
	(\texttt{idx = x.norm(dim=1).sort(descending=True).indices}).  
	After re‑ordering we apply a row encoder
	\texttt{Linear(d,64) → ReLU → Linear(64,64)}
	and feed it into the head \texttt{Linear(64,d\_out)}.
%	
	%------------------------------------------------------------------------
	\item \textbf{Full symmetrisation}
%	
	\textit{Theory.}  
	The average
	\(\bar f(X)=|S_N|^{-1}\sum_{P\in S_N} f (PX) \) is analytically invariant.
%	
	\textit{Implementation.}  
	For \(N\! = \!6\) we enumerate all permutations with
	\texttt{itertools.permutations}.  
	Each permuted set passes through the same MLP
	(\texttt{Linear → ReLU → mean}), the results are accumulated and divided by \(N!\).
%	
	%------------------------------------------------------------------------
	\item \textbf{Sampled symmetrisation}
%	
	\textit{Theory.}  
	We approximate the group average with
	\(\hat f_K(X)=K^{-1}\sum_{k=1}^K f(P_kX)\), where \(P_k\) are i.i.d. uniform
	permutations.
%	
	\textit{Implementation.}  
	We sample \(K=0.05 \cdot N!\) ,$(N=8)$ permutations  with
	\texttt{torch.randperm(N)}.  
	Inside the loop we apply the row MLP, \emph{mean‑pool}, and accumulate into a
	vector of shape \((d_{\text{out}},)\).  
	Finally we divide by \(K\).
%	
	%------------------------------------------------------------------------
	\item \textbf{Linear \(S_N\)‑equivariant network}
	
	\textit{Theory.}  
	Every \emph{permutation‑equivariant} linear map
	acting on an \(N\times d_{\text{in}}\) tensor (see Lec.\;10)
	must have the following form
	\[ \label{eq:equivariance}
	(\Phi X)_i \;=\;
	X W_1 \;+\;
	\boldmath{1} \boldmath{1}^T X W_2  .
	\]
	Stacking such \(\Phi\)’s with preserves equivariance; a final
	row‑sum makes the overall map invariant.
	
	\textit{Implementation.}  
	The layer below realises Eq.\eqref{eq:equivariance}
	\begin{lstlisting}[language=Python,basicstyle=\ttfamily\small,
		caption={Equivariant layer in PyTorch}]
		class Linear_eq_layer(nn.Module):
		def __init__(self, d_in=10, d_hidden=32):
		super().__init__()
		self.w1 = nn.Linear(d_in,d_hidden)
		self.w2 = nn.Linear(d_in,d_hidden)
		def forward(self, x):  # x is (n, d_in)
		return self.w1(x) + self.w2(torch.unsqueeze(torch.sum(x,dim=0),dim=0))
	\end{lstlisting}
	\emph{Equivariance test.}  
	property was verified separately.\\
	Followed by two such layers,
	ReLU activations, row‑sum pooling, and a head \texttt{Linear(d\_h,d\_out)}.
	\begin{lstlisting}[language=Python,basicstyle=\ttfamily\small,
		caption={Stacked equivariant layers in PyTorch}]
		class Linear_eq_Net(nn.Module):
		def __init__(self, d_in=10, d_hidden=32 , d_out = 4):
		super().__init__()
		self.equiv = nn.Sequential(Linear_eq_layer(d_in,d_hidden),
		nn.ReLU(),
		Linear_eq_layer(d_hidden,d_hidden)
		)
		
		self.post_pool = nn.Sequential(
		nn.ReLU(),
		nn.Linear(d_hidden, d_out))
		def forward(self, x):  # x is (n, d_in)
		x_eq = self.equiv(x)
		x_pool = x_eq.sum(dim=0)
		return self.post_pool(x_pool)
	\end{lstlisting}
\end{enumerate}
